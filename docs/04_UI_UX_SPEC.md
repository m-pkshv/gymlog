# 04_UI_UX_SPEC — Спецификация UI/UX

## 1. Назначение документа
Определяет карту экранов, навигацию, состояния экранов (загрузка/пусто/ошибка), подтверждения, модальные окна, клавиатуру, жесты и их альтернативы, адаптацию, доступность, темы и правила локализации. Бизнес-правила — `03_TECHNICAL_SPEC.md`; поля и валидация — `06_DATA_MODEL.md`.

## 2. Область ответственности
Поведение и структура интерфейса. Не входит: пиксельные макеты (создаются в коде на базе Material 3 с токенами раздела 9), формулы и хранение.

## 3. Принципы
1. Контекст спортзала (`01`, раздел 4): крупные касания (мин. 48×48 dp), важные действия — в нижней половине экрана, минимум обязательного ввода.
2. Ни одно действие не выполняется **только** жестом (ТЗ): у каждого жеста есть кнопочная альтернатива (раздел 8).
3. Автосохранение: интерфейс не содержит кнопок «Сохранить» в редакторах подходов/тренировки; изменения фиксируются сразу (`03`, раздел 5).
4. Деструктивные действия — подтверждение или Undo (`06`, раздел 10).
5. Material 3, `ColorScheme.fromSeed`, системные компоненты; кастомные виджеты — только при отсутствии стандартного.

## 4. Карта экранов и навигация
Нижняя навигация (5 вкладок): **Сегодня · История · Упражнения · Статистика · Ещё**.

**S-04 «Активная тренировка» как отдельный экран не построен** (Этап 4, решение владельца, подтверждено повторно на редизайне) — весь режим выполнения (таймер тренировки, отметки, таймер отдыха) живёт внутри S-03 (`WorkoutEditorScreen`, тот же экран для черновика/плана/активной/завершённой тренировки, меняется только видимый набор элементов по статусу). Ссылки на «S-04» ниже — историческое обозначение этого поведения внутри S-03, не отдельный маршрут.

```
Сегодня (S-01)
История (S-02) ─ Редактор тренировки (S-03, включает режим S-04) ─ Итог (S-05)
Упражнения (S-06) ─ Карточка упражнения (S-07) ─ Форма упражнения (S-08, модаль)
Статистика (S-09) ─ Прогресс по упражнению (S-10)
Ещё (S-11): Шаблоны (S-12) ─ Редактор шаблона (S-13)
            Измерения тела (S-14) ─ Форма измерения (S-15, модаль)
            Резервная копия (S-16, переименовано из «Импорт/экспорт», Этап 11)
            Настройки (S-17)
            Теги (без номера — добавлен Этапом 10, 2026-07-23)
            Профиль (без номера — добавлен Этапом 11)
```
- Фактические маршруты go_router (`lib/app/router.dart`): `/today`, `/history`, `/exercises` (`+:exerciseId`, `+:exerciseId/edit`, `+new`), `/stats` (`+exercise/:exerciseId`, `+exercise-search`), `/more` (`+templates/:templateId`, `+tags`, `+measurements` (`+new`, `+custom/:typeId`, `+girths`), `+export` (`+format`), `+settings`, `+profile`). Экран тренировки и связанные с ним пикеры создания — **не** вложены ни в одну вкладку: `/workout/:workoutId` (`+summary`, `+add-exercise`, `+edit-exercise/:exerciseId`), `/copy-source`, `/template-source` — все они верхнеуровневые маршруты-соседи вкладочного шелла (Этап 10, редизайн, найденный владельцем баг: вложенность в ветку «Истории» заставляла `StatefulShellRoute` переключать активную вкладку на «Историю» при открытии и «застревать» там после возврата, независимо от того, с какой вкладки тренировку открыли на самом деле).
- Кнопка «назад» Android везде ведёт на предыдущий экран; на корне вкладки — стандартное поведение выхода.

## 5. Спецификации экранов
Формат: назначение → ключевые элементы → действия → особые состояния. Общие состояния — раздел 6.

**S-01 Сегодня.** Список всех тренировок с датой сегодня (любой статус — была/идёт/будет) и всех будущих (любой статус), по дате; каждая карточка — статус, упражнения, кнопка «Начать» (только для `draft`/`planned`, иначе только тап-открыть) (Этап 10, 2026-07-24, решение владельца — было «только ближайшая draft/planned», вводило в заблуждение). При активной (`inProgress`) тренировке — отдельная карточка «Продолжить» сверху списка (не дублируется внутри списка). Ниже — быстрые действия одной строкой: пунктирная кнопка «+ С нуля» (текстовая, занимает основную ширину) + две круглые icon-only кнопки с тултипами «Из шаблона»/«Скопировать прошлую» (Этап 10, редизайн — было три равных текстовых кнопки). Пустое состояние (нет ни активной, ни единой тренировки в списке): приветствие + те же действия.

**S-02 История/Календарь.** Переключатель «Список / Календарь» (месяц с точками-статусами). Фильтры (bottom sheet): диапазон дат, текст по названию, статусы (мультивыбор), теги (мультивыбор; скрытые теги не показываются в фильтре при `showTags = 0`). Список: виртуализация скролла через `ListView.builder`, без пагинации (LIMIT/OFFSET) — требование снято на Этапе 10, 2026-07-22, замер на 1000 тренировок дал 71 мс, `ListView.builder` сам по себе достаточен на этом масштабе (`03`, раздел 11.6). Карточка = дата, имя, статус-чип, теги, число упражнений, длительность. Действия по карточке: открыть; меню «⋮»: копировать, создать шаблон, экспортировать в PDF (Этап 11, владелец: отправка файла без захода в тренировку), удалить (Undo). Перенос даты — внутри редактора (S-03), не в этом меню. FAB «Новая тренировка».

**S-03 Редактор тренировки.** Один и тот же экран для черновика/плана/активной/завершённой тренировки — набор видимых элементов меняется по статусу, отдельного экрана S-04 нет (см. раздел 4). Шапка (AppBar): имя (тап — переименование), дата (нажатие — перенос, недоступно при `inProgress`), статус-чип с меню переходов (только разрешённые — `06`, 6.4.1) + «Удалить» (Undo); при `inProgress` — компактный тап-чип таймера тренировки (пауза/продолжить по тапу) вместо статус-чипа. Под шапкой: теги (чипы + иконка-ярлык — назначение/снятие только здесь, создание/удаление тегов вынесено на отдельный экран «Ещё → Теги»), комментарий тренировки. Список упражнений: карточки с превью подходов; reorder — **только** меню «⋮ → Вверх/Вниз» (drag-жест был и убран целиком, Этап 10, 2026-07-28, решение владельца: заметно тормозил на устройстве, кнопки — единственный способ). Карточка упражнения сворачивается/разворачивается тапом по шапке (иконка типа + название, отдельно от меню «⋮» — Этап 10, 2026-07-24, решение владельца): свёрнуто показывает только название + шеврон состояния, состояние по умолчанию — развёрнуто, не персистентное (сбрасывается при повторном открытии экрана). В карточке упражнения: подходы — свёрнутая/развёрнутая строка (`ExpandableSetRow`): свёрнуто — № подхода, план-лейбл, крупное комбинированное значение факта; тап разворачивает степперы ±шаг (тап по числу — точный ввод в диалоге); при `inProgress` — отметка «✓» выполнения. Удаление подхода — **только кнопка**-корзина, Undo (свайп/`Dismissible` убран целиком, Этап 10, 2026-07-28, решение владельца — оказался главным источником фриза при скролле); комментария подхода нет (убран Этап 10, 2026-07-24, в пользу кнопки удаления). Кнопки «+ Подход», «Дублировать подход» (копирует план последнего подхода, показывается только если у него уже что-то заполнено); «Копировать показатели прошлого выполнения»; «Прошлые результаты» (bottom sheet с последними 5 выполнениями); решение о прогрессии (сегмент: —/↑/=/↓) с подсказкой «N без роста»; комментарий упражнения (убран Этап 10 (редизайн) 2026-07-26, возвращён Этап 11 2026-07-28 — владелец, тот же автосейв-контракт TS 5, что у комментария тренировки); «Переименовать упражнение»/«Редактировать упражнение» (только пользовательское — открывает полную форму S-08, Этап 10, 2026-07-28); удалить упражнение (Undo). При `inProgress` — таймер отдыха (`RestTimerCard`, появляется после отметки подхода, если автозапуск): полоса с остатком, ±15 с, пропустить. Кнопка «+ Упражнение» → выбор из каталога (поиск, без остальных фильтров каталога) с кнопкой «Создать новое»/«Скопировать из...» (S-08 модально; после создания сразу добавляется). Низ экрана (закреплён): одна главная CTA-кнопка статуса — «Запланировать»/«Начать»/«Завершить»/«Возобновить» (остальные переходы — в меню статус-чипа выше). Поведение таймеров при сворачивании/восстановлении процесса — `03`, раздел 7; баннер-напоминание об активной тренировке на других вкладках существовал (Этап 4) и был убран целиком (Этап 10, редизайн, 2026-07-26, решение владельца) — карточка «Продолжить» на S-01 сочтена достаточной.

**S-05 Итог тренировки.** Длительность (крупная карточка-«герой»), число упражнений/подходов, тоннаж, новые рекорды (если есть, сгруппированы по упражнению), поле комментария, решения прогрессии по упражнениям (можно проставить здесь), кнопка «Экспортировать в PDF» в AppBar (Этап 11), кнопка «Готово» → История.

**S-06 Упражнения.** Поиск (по имени, все локали имени), фильтры (bottom sheet): тип, мышечная группа (+«Без группы мышц»), оборудование (+«Без оборудования»), «показывать архивные» (выкл. по умолч.), «только пользовательские» — Этап 10, редизайн: список без активных фильтров сгруппирован секциями по основной группе мышц (канонический порядок, не алфавитный), плитка — цветной круглый аватар по группе мышц вместо иконки-заглушки; узкая полупрозрачная колонка точек-якорей у правого края для быстрого перехода по секциям (протяжка/тап). FAB «Создать» → S-08. Тап по плитке → S-07.

**S-07 Карточка упражнения.** Изображение (или плейсхолдер), имя, тип, группы мышц, оборудование, описание, YouTube-ссылка — **текстом, без кнопки** (Этап 2, решение владельца: `url_launcher` не входит в согласованный стек TS 3, добавлять не стали). Вкладки: «О упражнении» / «История» (последние выполнения); отдельной вкладки «Рекорды» нет — личные рекорды упражнения показываются на «Статистика → Прогресс по упражнению» (S-10), заводить дублирующий UI здесь сочли избыточным. Действия: редактировать (пользовательское; встроенное — только архивировать), архивировать/разархивировать, удалить (только неиспользованное пользовательское, `06`, раздел 10).

**S-08 Форма упражнения (модаль).** Поля: имя (обяз.; проверка на дубль среди всех упражнений, встроенных и пользовательских — Этап 10), тип (неизменяем при наличии истории — поле блокировано с пояснением), группа мышц, доп. группы (мультивыбор), оборудование, метрика усилия (для силового), описание, YouTube-ссылка (текстом при показе, см. S-07), раздел «Локализация» (до 2 карточек ru/en — название+описание перевода; доступно только при создании/редактировании, т.к. форма для встроенных недоступна — Этап 10). В режиме создания — кнопка «Скопировать из...» (Этап 10): открывает лёгкий поиск-пикер по всему каталогу, подставляет все поля выбранного упражнения (без локализаций), имя нужно переименовать самостоятельно (дубль имени не разрешён). Кнопка «Создать»/«Сохранить» активна при валидном непустом имени.

**S-09 Статистика.** Секции-карточки: Вес тела, % жира, Замеры (выбор типа), Тренировки (число/частота/тоннаж), «Прогресс по упражнению» (поиск упражнения → S-10). Каждый график: переключатель периода (Нед/Мес/3М/Год/Всё/Свой — range picker), значения в единицах настройки.

**S-10 Прогресс по упражнению.** Для strength/reps: графики макс. веса, расчётного 1ПМ (пометка «расчётный»), тоннажа; таблица «повторения при весе». Для cardio: дистанция, темп, длительность. Рекорды списком (значение, дата, ссылка на тренировку).

**S-12/S-13 Шаблоны.** Список (имя, число упражнений, меню: создать тренировку, дублировать, архивировать, удалить). Редактор — как S-03, но без статусов/дат/фактов; только структура и плановые значения (сворачивание карточки упражнения — тот же паттерн, что в S-03). «Создать тренировку из шаблона» → выбор даты → открывается S-03.

**S-14/S-15 Измерения.** Вкладки по типам (Вес, % жира, Замеры, Свои). Список записей по датам; график сверху. «+» → форма: тип, дата (def сегодня), значение (единицы настройки). Дубликат за день — диалог «Заменить существующее значение?». Управление пользовательскими типами — здесь же («Добавить замер…»). Вкладка «Замеры» — экран массового ввода: список всех обхватов с полем значения рядом с каждым, вместо выбора по одному через выпадающий список (Этап 10, 2026-07-23, решение владельца).

**S-16 Резервная копия** (переименовано из «Импорт/экспорт», Этап 11, решение владельца — резервное копирование БД теперь основная функция экрана). Две большие кнопки резервной копии сверху («Экспортировать резервную копию» — обычный синий; «Восстановить из резервной копии» — акцентный оранжевый цвет, как у «Завершить тренировку»), затем разделительная полоса, затем кнопка «Экспортировать данные (CSV)» → прогресс → системный share, затем ссылка «Описание формата CSV» (встроенная справка из `03`, раздел 10). Раздел «Импорт» (заглушка) и журнал операций экспорта — оба удалены целиком (Этап 11, 2026-07-31, решение владельца: не давали пользы пользователю).

**S-17 Настройки.** Система единиц (метрическая/имперская), тема (системная/светлая/тёмная), язык (системный/RU/EN), «Показывать теги» (переключатель; выключение скрывает чипы и фильтр тегов, данные не меняются), таймер отдыха по умолчанию + автозапуск, «Уведомления» (статус + переход в системные настройки), «О приложении» (версия, версия формата экспорта).

**Теги** (без номера в исходном ТЗ, добавлен на «Ещё» Этапом 10, 2026-07-23). Список всех тегов (цветной кружок + локализованное название — 17 встроенных по группам мышц переводятся, пользовательские показываются как есть). FAB «+» открывает диалог создания (имя + выбор цвета из палитры, раздел 9). Иконка-корзина на каждой строке — удаление с диалогом-подтверждением, показывающим число затронутых тренировок (`06`, раздел 10; без Undo после, в отличие от остальных Undo-удалений). Переименование/смена цвета существующего тега не предусмотрены (только создание/удаление). Назначение тегов конкретной тренировке — отдельно, в шторке S-03 (только выбор чипами, без создания/удаления — разведено намеренно, чтобы не путать снятие тега с его удалением).

**Профиль** (без номера в исходном ТЗ, добавлен на «Ещё» Этапом 11). Поля: никнейм, имя, фамилия (все опциональны, автосохранение по потере фокуса каждого поля независимо); аватар — круглое фото, тап открывает шторку «Сделать фото» (камера) / «Выбрать из галереи» / «Удалить фото» (если задано); фото ограничивается по размеру при выборе (512px/85% качества) до записи на диск. Данные используются в шапке PDF-экспорта тренировки (S-02/S-03/S-05).

## 6. Общие состояния экранов
| Состояние | Паттерн |
|---|---|
| Загрузка | Первичная — центрированный `CircularProgressIndicator` на весь экран (UX-3, Этап 9: упрощение исходного требования skeleton-плейсхолдеров, подтверждено владельцем); операции — линейный прогресс/disabled кнопка со спиннером |
| Пустое | Иллюстрация-иконка + 1 строка объяснения + основное действие (каждый список обязан иметь дизайн пустого состояния); экраны-пикеры (выбор источника для копирования и т.п.) могут ограничиться текстом без иконки/действия — там нет отдельного «основного действия» кроме возврата назад |
| Ошибка | Хранилище: экранная заглушка «Не удалось загрузить» + «Повторить» (перечитывает данные заново, не просто обновляет экран); операционные ошибки — snackbar с текстом из `AppError` (локализованным); ошибка миграции — блокирующий экран (`06`, раздел 11) |
| Подтверждения | Деструктивные без Undo — AlertDialog (заголовок-вопрос, «Отмена» слева, действие справа, деструктивное — красным); с Undo — snackbar 5 с «Удалено · ОТМЕНИТЬ» |
| Модальные окна | Формы создания — полноэкранные модали (safe area); выборы/фильтры — bottom sheet с ручкой-индикатором |

## 7. Клавиатура и ввод
- Числовые поля — `TextInputType.numberWithOptions(decimal:)`; принимаются `.` и `,` (`03`, раздел 6).
- Открытая клавиатура не перекрывает активное поле: `Scaffold.resizeToAvoidBottomInset = true` + автопрокрутка к полю (`ensureVisible`).
- «Done/Next» на клавиатуре: Next между полями формы, Done подтверждает и снимает фокус (триггер автосохранения).
- Ввод значений подхода — единый степпер-виджет (`NumericStepperField`, S-03, включает и черновик, и активный режим): ±шаг кнопками либо тап по числу → диалог точного ввода; tap-мишень значения ≥ 48 dp.

## 8. Жесты и обязательные альтернативы
Принцип раздела 3.2 (ни одно действие не требует жеста) на практике довели до предела: за Этап 10 из приложения убраны сами жесты, а не только их эксклюзивность — сейчас в MVP **нет** drag-and-drop и нет swipe-to-delete нигде, остались только кнопки.
| Было | Что осталось |
|---|---|
| Drag-and-drop порядка упражнений (ручка-иконка + меню «⋮») | Только меню «⋮» → «Переместить вверх/вниз» — ручка убрана целиком (Этап 10, 2026-07-28, владелец: тормозила скролл на устройстве, оказалась главным источником замеренного джанка редактора тренировки) |
| Swipe для удаления подхода (`Dismissible` + кнопка) | Только кнопка-корзина — свайп убран целиком (Этап 10, 2026-07-28, та же причина: тот же класс проблемы производительности) |
| Swipe между вкладками карточки упражнения (`TabBarView`, стандартное поведение Flutter) | Осталось как есть — тапы по вкладкам работают всегда, свайп — не единственный способ |
| Long-press для мультидействий | Не используется в MVP |

## 9. Темы и стиль
- Material 3. Seed-цвет: `#4C7BD9`. Светлая и тёмная темы — из одного seed (`ColorScheme.fromSeed(brightness:)`); режим — из настройки (def системный).
- Этап 10 (редизайн) добавил два семантических цветовых семейства сверх стандартной M3-палитры сида (`lib/app/design_tokens.dart`, `AppSemanticColors`, `ThemeExtension`): **accent** — энергичный оранжевый (CTA «Завершить тренировку», таймер отдыха; light `#E76C2B`/container `#FFDCC7`, dark `#FA8C58`/container `#3D2013`) и **success** — зелёный (отметка «выполнено», статус «Завершена», позитивные дельты; light `#2C974F`/container `#C9F1D0`, dark `#62BB78`/container `#163825`).
- Цвета статусов тренировки (`workoutStatusColors()`, роли `ColorScheme`, новых токенов под них не заводили): `draft`/`planned` — нейтральный (`surfaceContainerHighest`), `inProgress` — `primary`, `completed` — `success` (новый токен выше), `skipped` — `tertiary`, `cancelled` — `error`.
- Палитра тегов (8 цветов на выбор): `#4C7BD9 #2E9E6B #D9774C #B34CD9 #D9B84C #4CC3D9 #D94C6B #7B8794`.
- Крупные цифры (таймеры, тоннаж, значения степперов) — вес 900, табличные цифры (`AppNumberTextStyles`, Этап 10 редизайн). Отступы/радиусы — из шкалы `AppSpacing`/`AppRadius`, не магические числа. Кнопки (`FilledButton`/`ElevatedButton`/`OutlinedButton`/`TextButton`) — глобально скруглённый прямоугольник через тему (`IconButton` намеренно не входит — остаётся круглым, стандартный вид).
- Типографика — системная (Roboto/SF); масштаб текста пользователя уважается до 1.6× без поломки макетов (проверено вживую на эмуляторе, Этап 10; систематической проверки на реальных устройствах не было).
- Запрещено кодировать цвета в виджетах напрямую — только через `Theme`/`ColorScheme` и токены выше (единственное подтверждённое владельцем исключение — белая галочка на цветном свотче тега в диалоге создания тега: фон свотча сам не из темы, а из фиксированной палитры выше, галочке нужен контраст против произвольного цвета).

## 10. Адаптация под размеры экранов
- Базовый диапазон: ширина 320–480 dp (телефоны), портрет. Макеты — резиновые: `Expanded/Flexible`, без фиксированных ширин контента.
- Малые экраны (320 dp): таблица подходов сокращает подписи до иконок; проверка в ручных чек-листах.
- Планшеты: то же телефонное расположение с ограничением ширины контента 600 dp по центру. Safe area учитывается на всех экранах (вырезы, home-индикатор).

## 11. Доступность (accessibility)
- Все интерактивные элементы: мин. 48×48 dp, `Semantics`-подписи (иконки без текста обязаны иметь label).
- Поддержка TalkBack/VoiceOver: порядок фокуса соответствует визуальному; отметка подхода озвучивается («Подход 2, выполнен»).
- Контраст текст/фон ≥ 4.5:1 в обеих темах (проверять токены).
- Динамический размер шрифта — раздел 9. Состояния передаются не только цветом (статусы имеют текст/иконку).

## 12. Локализация
- ARB (`app_ru.arb`, `app_en.arb`); ключи — англ. camelCase; плюрализация через ICU (`{count, plural, ...}`) — обязательна для «N тренировок/подходов/дней».
- Русские строки длиннее английских в ~1.3×: макеты проверяются на RU; переполнение — `TextOverflow.ellipsis` + полный текст в tooltip/деталях; переносы не ломают кнопки (мин. высота фикс.).
- Даты/числа отображения — через `intl` по локали приложения; **хранение и CSV — независимо от локали** (`03`, раздел 10).
- Встроенные упражнения/группы мышц/оборудование — локализуются (ключи `06`, раздел 5). Пользовательский контент не переводится.
