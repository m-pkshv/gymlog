## Технические находки этой сессии (уроки, всё ещё актуальные)

- **Работа с изображениями без Python/ImageMagick**: ни `python3`/`python`, ни `magick` не оказались доступны в этой рабочей среде. Вместо них — PowerShell + `Add-Type -AssemblyName System.Drawing` (.NET), полностью рабочий путь для попиксельной обработки (`GetPixel`/`SetPixel`, `Graphics.DrawImage` для масштабирования/композитинга, `GraphicsPath`+`SetClip` для симуляции масок круга/скруглённого квадрата). Медленно (SetPixel в цикле по 1254×1254 ≈ 1.5М пикселей отработал в пределах 120с таймаута, но это не быстро) — для картинок покрупнее стоит закладывать больше времени или искать способ векторизовать обработку.
  - `Bitmap.GetPixel` на индексированных/1×1 PNG может вернуть пустые/некорректные значения — лечится копированием через `Graphics.DrawImage` в новый `Bitmap` с явным `PixelFormat.Format32bppArgb` перед чтением пикселей.
- **Вставленная прямо в текст сообщения картинка — не файл на диске.** Она видна мне как изображение в разговоре, но нет пути для `Read`/`Bash`. Если картинка нужна как реальный файл (например, для обработки/генерации иконок) — либо просить владельца прислать как вложение файла, либо (если тоже не сработало — вставка через буфер обмена не создаёт файл) искать её среди недавно изменённых файлов в стандартных папках (`~/Desktop`, `~/Downloads`, `~/Pictures`) через `find ... -newermt "ГГГГ-ММ-ДД ЧЧ:ММ"`, обычно нейросети/скриншот-инструменты сохраняют файл с автосгенерированным UUID-именем — сверить содержимое с тем, что видно в чате, прежде чем использовать.
- **Смена `applicationId`/`namespace`** — для Android физически перемещает пакет: нужно и поменять строку в `build.gradle.kts`, И переместить Kotlin-файлы (`MainActivity.kt`/`MainApplication.kt`) в новый путь каталога, совпадающий с новым `package`, иначе сборка не найдёт классы.
- **Смена `applicationId` = для Android это буквально другое приложение.** Установка новой сборки не обновляет старую (с другим id) — ставится ОТДЕЛЬНО, рядом. Если на телефоне есть тестовые данные под старым id — предупредить владельца ПЕРЕД установкой, не постфактум; уточнить, что делать со старым приложением (оставить второй копией / удалить).
- **`flutter_launcher_icons`/`flutter_native_splash` конфиг** — top-level ключи в `pubspec.yaml` (`flutter_launcher_icons:`, `flutter_native_splash:`), НЕ вложены в секцию `flutter:`. Запуск — `dart run flutter_launcher_icons` и `dart run flutter_native_splash:create` по отдельности.
- **Адаптивная иконка Android** — если исходный арт не содержит прозрачности (сплошной цветной фон впаян в пиксели), передний план можно извлечь по цветовому порогу (например, по каналу, который резко отличается у фона и у символа) с линейной растушёвкой альфы на границе, чтобы не было рваных краёв. Обязательно проверять итоговый bounding box символа относительно безопасной зоны (~66% диаметра от центра) — иначе широкие/нестандартные силуэты обрежутся на части лаунчеров при маскировке в круг. Проверять визуально: собрать композит символа под маской-кругом (худший случай) и маской-скруглённым-квадратом (типичный случай) и посмотреть глазами, а не только считать проценты.
- MIUI `INSTALL_FAILED_USER_RESTRICTED` иногда требует не просто повторной попытки, а **разблокировки экрана телефона** (диалог подтверждения установки не проходит через adb, пока экран заблокирован) — уже было отмечено раньше как «обычно решается повторной попыткой», в этот раз конкретно помогла разблокировка.
- Путь к adb на этой машине: `/c/Users/Mak/AppData/Local/Android/Sdk/platform-tools/adb.exe` (bash) — `export ANDROID_ADB=...` и вызывать через `"$ANDROID_ADB"`.

- Маленькие шаги: правка → `flutter analyze` + `flutter test` зелёные → коммит **только по явному запросу**.
- Неоднозначность, задевающая данные/схему/новые зависимости/подпись релиза — сначала `AskUserQuestion`, потом код.
