## Технические находки этой и предыдущих сессий (уроки, актуальны и дальше)

- **`ColorScheme.fromSeed()` — не бесплатная операция.** Если что-то (провайдер, виджет) слушает целиком объект без переопределённого `==`, любое несвязанное изменение поля вызовет полный пересчёт зависимых значений — при подозрении на лишнюю работу при рутинных апдейтах стоит проверить именно это, не только «дорогие» операции типа сортировки/сети.
- **`flutter_lints` НЕ включает `prefer_const_constructors`/`prefer_const_literals_to_create_immutables`/`prefer_const_declarations` по умолчанию** — только более узкий `prefer_const_constructors_in_immutables`. Теперь включены в `analysis_options.yaml` явно — это постоянный страж, не разовая проверка.
- **`flutter build appbundle --strip` — не существующий флаг** (несмотря на то, что именно его предлагает предупреждение сборки и некоторые статьи в интернете). Единственный способ прокинуть `--strip` — через `--extra-gen-snapshot-options=--strip`, но это ЛОМАЕТ сборку («failed to strip debug symbols from native libraries»), т.к. конфликтует с собственным шагом стриппинга у Android Gradle Plugin. AGP и так стрипает нативные библиотеки на своём этапе — предупреждение относится к промежуточному состоянию файла, не к финальному `.aab`. Проверять реальный результат напрямую (`llvm-readelf -S` из Android NDK на распакованных `.so`), не доверять тексту предупреждений/форумов на слово.
- **Современный `keytool` создаёт keystore в формате PKCS12 по умолчанию** (несмотря на расширение `.jks`) — PKCS12 не поддерживает разные пароли для хранилища и ключа, JDK молча использует один и тот же пароль для обоих, игнорируя явно заданный `-keypass`.
- **MIUI иногда требует физического подтверждения на экране телефона** при `adb install` нового пакета/подписи — если команда падает с `INSTALL_FAILED_USER_RESTRICTED: Install canceled by user`, стоит проверить экран устройства на диалог, а не считать это стабильной ошибкой adb.
- **Android не даёт установить пакет с другой подписью поверх уже установленного** (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`) — при переходе с debug- на release-подпись (или наоборот) старое приложение сначала нужно удалить, что стирает его локальные данные на устройстве. Это разрушительное действие — спрашивать явное подтверждение владельца перед этим, не делать молча.
- **XML-комментарии: двойной дефис `--` внутри тела комментария невалиден** и валит сборку (`AndroidManifest.xml`, `keep.xml` и т.п.) — уже несколько раз находили эту грабли в проекте, проверять новые/изменённые XML-комментарии на `--` до сборки.
- **Любой Android-ресурс, к которому обращаются по имени-строке** (`Resources.getIdentifier`), а не статической ссылкой `R.drawable.xxx`, невидим для resource shrinker'а release-сборок и рискует быть тихо вырезан — краш проявляется только в рантайме, только в release/profile. При любом похожем API сразу добавлять `tools:keep` (`android/app/src/main/res/raw/keep.xml`).

- Маленькие шаги: правка → `flutter analyze` + `flutter test` зелёные → коммит **только по явному запросу**.
- Неоднозначность, задевающая данные/схему/новые зависимости/подпись релиза/деньги/аккаунты — сначала `AskUserQuestion`, потом действие.
