## Что реализовано по PDF-экспорту (для контекста, прежде чем спрашивать про доработки)

- `lib/services/pdf/workout_pdf_service.dart` — `WorkoutPdfService.buildWorkoutPdf(...)`, строит `pw.Document` (пакет `pdf`). Шапка: аватар (если задан, через `pw.ClipOval`+`pw.MemoryImage`) + имя/фамилия/никнейм из профиля (если заполнены) + название/дата/статус/длительность/теги тренировки. Дальше: три плитки-показателя (упражнения/подходы/тоннаж, через уже существующий `computeWorkoutSummaryStats`), комментарий тренировки, секция «Новые рекорды» (если есть, та же логика фильтрации `record.workoutId == текущая тренировка`, что у экрана «Итог»), и по каждому упражнению — название/комментарий/таблица подходов план-факт-выполнено (через уже существующие `setFieldsFor`/`formatFieldsSummary` из редактора тренировки — те же формулы, что видны на экране).
- `lib/features/workout_editor/export_workout_pdf_flow.dart` — общая flow-функция (собирает профиль+рекорды, зовёт сервис, передаёт готовые байты в `Printing.sharePdf` из пакета `printing`), вызывается из ДВУХ точек: «⋮ → Экспортировать в PDF» в редакторе тренировки и кнопка-иконка в AppBar экрана «Итог тренировки».
- Шрифт: `assets/fonts/Roboto-{Regular,Bold}.ttf` (Apache License 2.0) — библиотека `pdf` не умеет в кириллицу во встроенных шрифтах (Helvetica/Times/Courier), поэтому пришлось embedd-ить полноценный TTF. Файлы взяты из уже присутствовавшей в pub-кэше DevTools-сборки пакетов `drift`/`riverpod` (тот же самый файл Roboto, который использует сам Android/Flutter, лицензия не накладывает ограничений на такое переиспользование).
- Имя файла: `workoutPdfFileName()` → `gymlog_workout_ГГГГ-ММ-ДД.pdf`.
- Тесты: `test/services/pdf/workout_pdf_service_test.dart` (5 тестов, включая отдельный тест на кириллицу в названии/комментариях/тегах/имени профиля — чистые доменные объекты, без БД, без платформенной границы) + 2 widget-теста (пункт меню/кнопка присутствуют, сам тап не выполняется — тот же принцип «не тестировать через реальный платформенный канал», что уже принят для `file_picker`/`path_provider`/`NotificationService`).

## Технические находки этой сессии (уроки, всё ещё актуальные)

- **Виджет-тесты выполняются в `FakeAsync`-зоне** — настоящий `dart:io` (реальные файловые операции внутри `testWidgets`) не гарантированно успевает завершиться до того, как `pumpAndSettle()` перестаёт качать кадры, даже если операция сама по себе быстрая. Чинится через `await tester.runAsync(() => Future<void>.delayed(Duration.zero));` сразу после действия, запускающего реальный I/O, перед следующим `pumpAndSettle()`.
- **`File(path).exists()`/подобные вызовы реально зависают на этой Windows-машине при смешанных разделителях пути** (`\` из `Directory.systemTemp.path` + `/` при ручной конкатенации `'${path}/filename'`) — не только у некорректных путей без буквы диска. Всегда строить путь через `Platform.pathSeparator`, не через ручной `'/'`.
- **Конфликт версий `win32` между пакетами** — `file_picker` (стабильные версии до 12.0.0-beta) требует `win32 ^5.9.0`, уже используемый `share_plus ^13.2.1` требует `win32 ^6.0.1`. Если `flutter pub add <pkg>` без версии резолвится в подозрительно старую версию — проверить, не конфликт ли это, и поискать более новую (в т.ч. бета) линию явно (`flutter pub add "pkg:>=X.Y.Z-beta.1"`).
- **Шрифты для PDF**: пакет `pdf` не поддерживает кириллицу во встроенных core-шрифтах — нужен embedded TTF. Открытые/легальные к переиспользованию шрифты (Apache 2.0/OFL) можно найти уже присутствующими локально в pub-кэше как часть DevTools-сборок других пакетов (`drift`/`riverpod`/`shared_preferences` бандлят Roboto для своего web-интерфейса) — не нужно искать в интернете (доступа всё равно нет в рабочей среде).
- **`Object` const-канонизация** — при добавлении маркеров действий в существующее `PopupMenuButton<Object>`-меню (как `WorkoutStatusMenu`) — всегда `enum`, никогда `const Object()` (см. существующий комментарий в файле про уже найденный этим способом баг на Этапе 10).
- Устройство иногда даёт `INSTALL_FAILED_USER_RESTRICTED`/теряет видимость в `adb devices` — обычно решается повторной попыткой; `adb install -r -d ...` (флаг `-d` разрешает даунгрейд версии без потери данных).
- Путь к adb на этой машине: `/c/Users/Mak/AppData/Local/Android/Sdk/platform-tools/adb.exe` (bash) — `export ANDROID_ADB=...` и вызывать через `"$ANDROID_ADB"`.
- Фоновые команды (`run_in_background: true`) в этой среде **буферизуют вывод** — файл вывода может оставаться пустым (или показывать только последние строки) до завершения процесса или его принудительного убийства; это не обязательно означает зависание — сверяй elapsed time процессов (`Get-Process`) прежде чем считать что-то реально подвисшим.
