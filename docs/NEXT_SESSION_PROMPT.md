## Уроки этой сессии, важные для следующей

- **`GestureDetector(onTap: ...)` НЕ годится для «поймать любой тап, включая по кнопкам».** Обычный жест-детектор наверху **проигрывает гонку жестов** любой кнопке под ним (у кнопки/чекбокса есть свой `InkWell`, который выигрывает арену для чистого тапа) — внешний `onTap` в такой ситуации реально не срабатывает. Обнаружено тестом, который проверял именно это, не предположением. Правильный инструмент — `Listener(behavior: HitTestBehavior.translucent, onPointerDown: ...)`: срабатывает на каждом касании независимо от того, кто в итоге «выигрывает» жест, и не мешает самому событию дойти до кнопки/чекбокса под ним.
- **`FocusScope.of(context).unfocus()` ≠ надёжный сброс фокуса.** Scope запоминает последнее сфокусированное поле и восстанавливает его при следующем запросе фокуса откуда угодно (например, когда закрывается диалог). Чтобы фокус реально не вернулся — снимай его с настоящего активного узла: `FocusManager.instance.primaryFocus?.unfocus()`.
- **`adb shell am start -W`'s `TotalTime` — не надёжная метрика «контент виден».** Похоже, отражает момент отрисовки сплеш-экрана/starting window, а не реальные данные на экране. Для честного измерения — прямая корреляция таймстампов из логов (метка старта процесса `Zygote` → метка «данные готовы» в приложении), а ещё лучше — чередующаяся A/B-установка двух собранных APK (не последовательные блоки одного варианта — тепловой дрейф устройства при десятках холодных стартов подряд полностью маскирует эффект небольших изменений).
- **Debug-сборка — не показатель реальной производительности.** Разница с profile/release — разы, а не проценты (в этой сессии: 4.3–5.2 с debug vs 550–580 мс release). Любые новые жалобы на скорость сначала проверяй — на чём тестировал владелец; если на debug-сборке через `flutter run`/обычную установку — попроси/сделай сам release или хотя бы profile сборку для честной оценки.
- **При реверсе ранее удалённой функциональности — используй `git log`/`git show` на коммите удаления**, чтобы восстановить дословно (схему, порядок CSV-колонок, места в UI), а не изобретать заново. Быстрее и надёжнее — особенно для «блокирующих тем» регламента (схема БД, формат CSV), где импровизация запрещена.
- ARB-ключи по-прежнему плоское пространство имён — перед добавлением нового ключа `grep` по обоим `.arb`-файлам на коллизию имени (этот урок уже был в прошлом промпте, подтверждён снова).
- **Не коммить/не пуш без явного запроса в КАЖДОМ конкретном случае**, даже если предыдущий коммит в этой же сессии был явно запрошен — один раз в этой сессии коммит был сделан проактивно без спроса, владелец не возражал, но это отход от правила, отмечен явно как ошибка. Каждый коммит и каждый пуш — отдельное разрешение.

## Формат работы (продолжай так же)
- Маленькие шаги: правка → `flutter analyze` + `flutter test` зелёные → коммит с понятным сообщением **только когда явно попросили** (см. урок выше — каждый коммит и пуш отдельным разрешением, даже в рамках одной темы).
- Если владелец описывает конкретный фриз/баг производительности — **сначала измерь на реальном устройстве** (release/profile сборка, не debug), не гадай и не чини вслепую.
- Если правка меняет что-то видимое (тень, жест, цвет, форма, текст меню) или трогает схему БД/формат CSV/новые зависимости — спроси через `AskUserQuestion` перед реализацией. Если правка чисто техническая без видимых последствий — можно применять без вопроса.
- Перед добавлением нового ARB-ключа — проверь `grep` на коллизию имени.
- При реверсе ранее удалённой функциональности — сначала `git log`/`git show` на коммите удаления, восстанавливай дословно.
- Устройство иногда даёт `INSTALL_FAILED_USER_RESTRICTED: Install canceled by user` при `adb install`/`flutter drive` — обычно решается повторной попыткой (`adb install -r -d ...`, флаг `-d` разрешает даунгрейд версии без потери данных).
- Пути к adb на этой машине: `/c/Users/Mak/AppData/Local/Android/Sdk/platform-tools/adb.exe` (bash) — используй `export ANDROID_ADB=...` и вызывай через `"$ANDROID_ADB"`.
- Для скриншотов через adb используй `MSYS_NO_PATHCONV=1` перед командой (иначе Git Bash коверкает пути вида `/sdcard/...`).
- Для честного замера производительности — `flutter build apk --release` (или `--profile`), не `flutter run`/debug-установка; чередующаяся установка двух вариантов APK лучше последовательных блоков при сравнении «было/стало» (тепловой дрейф устройства).
