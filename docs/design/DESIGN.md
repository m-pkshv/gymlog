# DESIGN.md — Дизайн-бриф для редизайна GymLog

Техническое задание на основе `AUDIT.md`. Предназначено для передачи дизайнеру (человеку или Claude Design) как самодостаточный документ — не требует чтения кода или переписки, предшествующей ему.

---

## 1. О продукте

GymLog — мобильный дневник тренировок для тренирующихся: планирование тренировок, ведение подходов в реальном времени во время тренировки, шаблоны, измерения тела, статистика прогресса и личные рекорды, экспорт данных в CSV. Полностью офлайн, без аккаунта и бэкенда — все данные хранятся локально на устройстве.

---

## 2. Список экранов

19 маршрутов, сгруппированных по 5 вкладкам нижней навигации. Экраны создания/редактирования (отмечены «модаль») открываются как full-screen modal поверх текущего экрана; остальные — обычным переходом внутри своей вкладки.

### Вкладка «Сегодня»
| Экран | Назначение | Ключевой контент |
|---|---|---|
| **Сегодня** (S-01) | Стартовый экран — что делать прямо сейчас | Карточка активной тренировки (если есть) ИЛИ список тренировок на сегодня/будущее; 3 кнопки быстрого создания тренировки |

### Вкладка «История»
| Экран | Назначение | Ключевой контент |
|---|---|---|
| **История** (S-02) | Журнал всех тренировок, поиск/фильтры | Список карточек тренировок (дата, статус, теги, длительность); переключатель список/календарь; поиск; фильтр по датам/статусам/тегам |
| **Выбор для копирования** (модаль) | Пикер источника при создании «Копией» | Список завершённых тренировок |
| **Выбор шаблона** (модаль) | Пикер при создании «Из шаблона» | Список сохранённых шаблонов |
| **Редактор тренировки** (S-03) | **Главный экран приложения** — ввод/просмотр тренировки, включая live-режим с таймерами | Дата, статус, теги, комментарий; список карточек упражнений, каждая с подходами (план/факт/чекбокс/удаление); в статусе «Выполняется» — доп. бегущий таймер тренировки и таймер отдыха между подходами |
| **Итог тренировки** (S-05) | Экран после «Завершить» | 4 показателя (длительность/упражнения/подходы/тоннаж); список новых личных рекордов (если есть); комментарий; решение о прогрессии по каждому упражнению |
| **Выбор упражнения** (модаль) | Добавление упражнения в тренировку/шаблон | Поиск по каталогу; кнопка «создать новое» |
| **Создание упражнения** (модаль) | Форма нового/редактируемого упражнения | Название, тип, группы мышц, оборудование, описание, YouTube-ссылка, локализация |

### Вкладка «Упражнения»
| Экран | Назначение | Ключевой контент |
|---|---|---|
| **Каталог упражнений** (S-06) | Просмотр/поиск базы упражнений (199 встроенных + пользовательские) | Поиск, фильтр (тип/группа мышц/оборудование/архив), плоский список |
| **Карточка упражнения** (S-07) | Детали одного упражнения | Тип, мышцы/оборудование, описание, вкладка истории выполнений |

### Вкладка «Статистика»
| Экран | Назначение | Ключевой контент |
|---|---|---|
| **Статистика** (S-09) | Обзорные графики | Карточки: динамика веса, % жира, замеров (график + переключатель периода); число/частота/тоннаж тренировок за период |
| **Выбор упражнения для прогресса** (модаль) | Пикер | Поиск по каталогу |
| **Прогресс по упражнению** (S-10) | Детальная статистика по одному упражнению | Графики (макс. вес/1ПМ/тоннаж или дистанция/темп/длительность) с переключателем периода; таблица «повторения при весе»; список личных рекордов |

### Вкладка «Ещё»
| Экран | Назначение | Ключевой контент |
|---|---|---|
| **Ещё** (меню) | Точка входа во второстепенные разделы | Список: Шаблоны / Теги / Измерения / Импорт-экспорт / Настройки |
| **Шаблоны** (S-12) | Список сохранённых шаблонов тренировок | Карточки шаблонов, действия (архив/удалить/дублировать/создать тренировку) |
| **Редактор шаблона** (S-13) | Тот же UI, что редактор тренировки, но без фактов/таймеров | Название, комментарий, карточки упражнений с плановыми подходами |
| **Теги** | Управление тегами тренировки | Список тегов (17 базовых по группам мышц + пользовательские), создание, удаление |
| **Измерения** (S-14) | Ввод/просмотр замеров тела | Вкладки Вес/%жира/Замеры/Свои; график + список записей; массовый ввод обхватов |
| **Импорт/экспорт** (S-16) | Экспорт данных в CSV | Кнопка экспорта, журнал операций, задизейбленный «Импорт» (пост-MVP), справка о формате |
| **Настройки** (S-17) | Конфигурация приложения | Тема, язык, единицы измерения, таймер отдыха по умолчанию, уведомления, о приложении |

**Отсутствующие/нереализованные экраны** (не в объёме этого редизайна, но дизайнер должен знать о них): онбординг первого запуска — сознательно отсутствует (решение владельца: пустые состояния обучают сами); экран импорта CSV — пост-MVP.

## 3. Текущая дизайн-система (буквально из кода)

**Важно для дизайнера**: почти ничего из перечисленного ниже не является «фирменным стилем», который нужно бережно сохранить — это стоковые дефолты Flutter Material 3, ни разу не кастомизированные. Единственное реальное ограничение — сид-цвет ниже (подтверждён владельцем как «оставить как есть»); всё остальное (типографика, spacing, radius, форма компонентов) можно спроектировать заново без оглядки на «традицию» продукта.

### Цвет
- Вся палитра (light и dark) генерируется алгоритмически Flutter из одного seed-цвета через `ColorScheme.fromSeed()` (Material 3 tonal palette). Ручных переопределений `primary`/`surface`/`error` и т.д. нет.
  ```dart
  const Color seedColor = Color(0xFF4C7BD9); // подтверждён владельцем, менять не нужно
  ```
- Единственная вручную заданная палитра в приложении — 8 фиксированных hex-цветов для тегов тренировки (не завязаны на тему, светлые/яркие оттенки, читаемы как на светлом, так и на тёмном фоне):
  ```
  #4C7BD9  #2E9E6B  #D9774C  #B34CD9
  #D9B84C  #4CC3D9  #D94C6B  #7B8794
  ```
- Обе темы (светлая и тёмная) обязательны — приложение переключается на лету («Настройки» → Тема: Системная/Светлая/Тёмная), редизайн должен работать в обеих.

### Типографика
- Кастомного `TextTheme` нет, кастомных шрифтов не подключено (`pubspec.yaml`) — используется системный шрифт платформы (Roboto на Android) и стоковая шкала размеров Material 3 без изменений.
- Дизайнер свободен выбрать любую типографическую систему — единственное техническое ограничение: должна поддерживаться через Flutter (Google Fonts пакет или бандл шрифта в ассеты — обе опции доступны, если дизайнер укажет конкретный шрифт).

### Spacing / radius
- Единой шкалы нет. В коде отступы заданы вручную по месту, встречающиеся значения: 4, 8, 12, 16, 24 (dp). Border-radius нигде не переопределён — используются дефолтные скругления Material 3-виджетов.
- Ожидание от редизайна: предложить закреплённую шкалу (например, 4/8/12/16/24/32) и значения radius для карточек/кнопок/полей ввода, которые команда разработки внедрит как токены темы.

### Переиспользуемые компоненты
- Общей библиотеки компонентов нет — почти каждый экран верстает свою `Card`/`ListTile`/кнопки напрямую. Единственные реально переиспользуемые элементы: `ErrorRetryState` (иконка + текст + кнопка «Повторить», используется на 27 экранах) и числовое поле ввода с настраиваемой клавиатурой.
- Следствие для дизайнера: можно закладывать полноценную систему компонентов «с нуля» (кнопки нескольких уровней, карточка, чип статуса, поле ввода с явным лейблом плана/факта, таблица подходов, таймер) — переиспользование по всему приложению не будет ломать существующие паттерны, потому что устоявшихся паттернов, по сути, нет.

### Иконки
- Стандартный набор Material Icons (`_outlined` вариант) без исключений. Дизайнер может предложить кастомный/более выразительный набор иконок (в т.ч. для типов упражнений/статусов), если это укладывается в объём проекта.

### Навигация
- Нижняя навигация, 5 фиксированных вкладок: Сегодня / История / Упражнения / Статистика / Ещё. Переструктурирование состава вкладок — вне объёма (архитектурное решение, не дизайн интерфейса).
- Формы создания/редактирования открываются как full-screen modal снизу вверх; просмотровые экраны — обычным переходом (slide) внутри вкладки.

## 4. Целевая аудитория и контекст использования

- **Кто**: люди, регулярно тренирующиеся с отягощениями/кардио, ведущие подробный лог (вес, повторения, подходы) — от новичков до опытных атлетов, отслеживающих прогрессию.
- **Где и как**: **основное использование — прямо в зале, между подходами.** Это определяет весь набор требований:
  - Одной рукой, часто на бегу к следующему снаряду.
  - Потные/скользкие пальцы — тач-зоны должны быть крупными и разнесёнными, особенно там, где рядом стоят действия с разной ценой ошибки (например, «отметить подход выполненным» и «удалить подход» — сейчас это два одинаковых по размеру элемента впритык, см. `AUDIT.md`, раздел 1.6).
  - Минимум чтения — решение «что вводить» должно считываться визуально (форма/расположение/цвет), а не текстовым лейблом, который нужно прочитать под нагрузкой и в спешке.
  - Таймер отдыха между подходами и общий таймер тренировки — это активные, тайм-чувствительные элементы, за которыми человек следит боковым зрением, кладя телефон рядом со скамьёй/на пол — они должны быть считываемы с расстояния и под углом, крупным шрифтом/цветом.
  - Освещение зала часто резкое верхнее или, наоборот, тусклое — важен высокий контраст в обеих темах (сейчас тёмная тема выглядит преобладающей на скриншотах).
- **Второстепенный контекст**: просмотр статистики/истории/настройка шаблонов — уже дома, спокойно, сидя, двумя руками — здесь ограничение на «крупные тач-зоны» не столь критично, можно позволить более плотную/информативную вёрстку (например, в каталоге упражнений, статистике).

## 5. Технические ограничения

- **Стек**: Flutter (Dart SDK ^3.12.2), Material 3 (`useMaterial3: true`). Cupertino-виджеты не используются нигде — приложение выглядит одинаково на Android и iOS (сознательное решение продукта, не тема пересмотра).
- **Платформы**: только Android (min SDK 26 / Android 8.0) и iOS (deployment target 13.0). Веб/десктоп — не поддерживаются и не планируются.
- **Обязательна поддержка обеих тем** — светлой и тёмной, переключаемых на лету без перезапуска.
- **Обязательна поддержка увеличенного системного масштаба текста** до 1.6× — макеты не должны ломаться (переполнения/обрезания) при увеличенном шрифте; уже была отдельная работа над этим (Этап 9), редизайн не должен её регрессировать.
- **Локализация RU/EN** — русский текст в среднем на ~30% длиннее английского; макеты не должны быть спроектированы «впритык» под короткие английские строки.
- **Минимальный тач-таргет 48×48dp** — уже соблюдается технически по всему приложению; редизайн не должен уменьшать интерактивные зоны ниже этого порога, особенно для соседних действий с разной ценой ошибки (чекбокс/удаление).
- **State management**: Riverpod, реактивные потоки данных из локальной SQLite-базы (Drift) — с точки зрения дизайна это означает, что почти любой список/значение может меняться «на лету» без явного «Обновить» — анимации появления/исчезновения элементов приветствуются, если укладываются в объём.
- Нет сети, нет облака, нет push-уведомлений извне — только локальные уведомления (таймер отдыха).

## 6. Явные проблемы текущего дизайна (что нужно решить)

В порядке приоритета (полный разбор — `AUDIT.md`):

1. **Редактор тренировки в статусе «Выполняется» (главный экран приложения)**:
   - Поля «план» и «факт» в строке подхода — два одинаковых пустых поля без подписи, какое из них что означает.
   - Чекбокс «подход выполнен» и кнопка удаления подхода — одинакового размера/цвета, расположены впритык — риск промаха потным пальцем между разными по цене ошибки действиями.
   - Подписи полей («Вес, кг», «Повторения») дублируются на каждой строке подхода вместо общей шапки таблицы — тратит вертикальное место, увеличивает скролл.
   - Бегущий таймер тренировки и таймер отдыха между подходами — самые тайм-чувствительные элементы экрана — визуально ничем не выделены среди обычного текста; таймер отдыха вообще не имеет цветовой/прогресс-индикации.
   - Системный баннер «Тренировка продолжается» наезжает на статус-бар (нет safe-area отступа) — визуальный дефект, требующий исправления.
2. **Нулевая визуальная иерархия во всём приложении** — заголовки, метаданные, ключевые числа и второстепенный текст визуально почти неразличимы по весу/размеру.
3. **Один цветовой акцент на всё** — нет семантического цвета для 6 статусов тренировки (черновик/план/в процессе/завершена/пропущена/отменена), решение о прогрессии показывается символами без подписи (—/↑/=/↓).
4. **Каталог упражнений (199 строк) визуально монотонен** — идентичные строки без дифференциации по типу/группе мышц/иллюстрации.
5. **Статистика не выделяет числа как главный контент** — ключевые метрики того же визуального веса, что подписи под ними.
6. **Экран-итога тренировки не использует момент похвалы** — «4 новых рекорда» подаются нейтрально, как список настроек, хотя это единственный экран, чья цель — вознаградить пользователя.
7. **Нижняя навигация и кнопки визуально «тихие»** — не рассчитаны на быстрое распознавание на бегу/боковым зрением.
8. Дизайн-системы как таковой нет (раздел 3) — редизайн стартует с чистого листа, а не «освежает» существующее.
