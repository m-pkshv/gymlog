## Формат работы в этой ветке (не как обычный поток этапов)

Владелец лично тестирует debug- или release-сборку на реальном устройстве и присылает находки **по одной** — обычно скриншот макета или фото экрана с описанием, что поправить. Каждая находка разбирается отдельно:
1. Если есть неоднозначность, влияющая на функциональность (не чисто косметика) — уточнить через `AskUserQuestion` **до** реализации.
2. Правка → `flutter analyze` (0 ошибок) → `flutter test` (полный набор, не только затронутый файл) → зелёные.
3. Собрать debug-сборку (`flutter build apk --debug`) и поставить на устройство владельца через `adb install -r -d` — **если владелец явно не попросил release-сборку** (один раз в этой сессии специально просил `flutter build apk --release`, тогда после установки ещё и явно проверял живой процесс через `adb shell am start` + `pidof`, т.к. release-сборки в этом проекте дважды ловили реальные краши, которых не было в debug — см. Этап 12 в `CLAUDE.md`).
4. Коммитить **только по явному запросу** владельца — обычно копится несколько шагов, потом одна просьба «закомить».
5. После каждого шага — короткая запись в `CLAUDE.md` (раздел «Редизайн интерфейса v2», формат «✅ Шаг N»: что сделано, что проверено, как проверить руками).

## Технические находки этой сессии (уроки, актуальны и дальше)

- **`CrossAxisAlignment.stretch` на `Row`/`Column` внутри `ListView`/любого скроллящегося (неограниченная по высоте ось) контекста — невалиден.** Бросает `BoxConstraints forces an infinite height` на каждом кадре, из-за чего `pumpAndSettle()` в widget-тестах никогда не завершается — выглядит как массовые случайные падения НЕСВЯЗАННЫХ тестов («флейк окружения»), а на самом деле реальный баг. Если видишь такой симптом — в первую очередь читай **начало** лога упавшего теста (не хвост), там будет настоящее исключение.
- `--plain-name "текст с пробелами"` у `flutter test` в этой шелл-обвязке (git-bash на Windows) падает с посторонней ошибкой про `E:\Program`. Обходится через `--name=текст.без.пробелов` (это regex, `.` матчит любой символ, в т.ч. пробел).
- Иногда фоновая (background) `flutter test`-команда, которая по `tasklist` выглядит «зависшей», на самом деле уже успешно завершилась (exit 0) прямо в момент проверки — не спеши считать зависание реальным, сначала проверь вывод через уведомление/`Read` на output-файл, и только потом `taskkill`.
- Debug-сборки не ловят некоторые классы багов, которые проявляются только в release (resource shrinker, обфускация) — если владелец просит именно release-сборку, не заменяй её debug молча.
