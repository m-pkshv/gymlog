# AUDIT.md — Аудит текущего UI/UX (GymLog)

Дата: 2026-07-24. Источники: 5 приложенных скриншотов (Сегодня, История, Упражнения, Статистика, Ещё) + кодовая база (`lib/app/theme.dart`, `lib/app/router.dart`, `lib/core/constants.dart`, `lib/main.dart`, `pubspec.yaml`, представительные экраны).

---

## 1. Наблюдения по скриншотам

### 1.1 «Сегодня»
- Контент: карточка ближайшей/сегодняшней тренировки (`Card`+`ListTile`) — название, дата/статус/число упражнений одной строкой мелким серым текстом, кнопка «Начать» справа. Ниже — три `OutlinedButton.icon` в один ряд («+ С нуля», «Из шаблона», «Копией»).
- Проблемы:
  - **Пустое, невыразительное пространство**: под кнопками — почти весь экран пуст, без визуального якоря, ощущается недоделанным.
  - **Нет иерархии между карточками**: сегодняшняя тренировка и будущая выглядят абсолютно одинаково (тот же серый `Card`), хотя по смыслу это разные по важности вещи.
  - Название и дата/статус — одного визуального веса, глазу не за что зацепиться в первую секунду.
  - Кнопка «Начать» — единственный цветной акцент на весь экран.

### 1.2 «История»
- Контент: поиск + иконки календаря/фильтра в AppBar, карточка тренировки (название, дата/кол-во упражнений/длительность, статус-чип «Завершена», меню «⋮»), под карточкой — цветной чип тега («● Бицепс»).
- Проблемы:
  - Статус-чип «Завершена» — просто обведённый прямоугольник с текстом, не считывается как статус с первого взгляда (нет цветового кодирования по статусу: черновик/план/выполняется/завершена/пропущена/отменена).
  - Тег вынесен отдельной строкой под карточкой, а не встроен в саму карточку — визуально «оторван».
  - Плотность информации в одной строке subtitle («24.07.2026 · 1 упражнение · 0 мин») — мелкий текст, много точек-разделителей, тяжело сканировать на бегу.
  - FAB внизу справа — стандартный синий круг без подписи, не выделяется на фоне интерфейса, где кнопки такого же синего цвета используются и для других целей.

### 1.3 «Упражнения»
- Контент: поиск + фильтр, плоский список `ListTile` без карточек — маленькая линейная иконка (одна и та же для типа «Силовое»), название, подпись «Тип · Группа мышц».
- Проблемы:
  - **Самый монотонный экран в приложении**: 199 визуально идентичных строк, единственное отличие — текст. Нет фото/иллюстрации/цветового кода по группе мышц или типу.
  - Иконка не несёт информации (одна и та же стрелка-квадрат почти для всех силовых упражнений).
  - Нет группировки/секций (по алфавиту, по группе мышц и т.п.) — просто сплошной список.
  - Разделителей между строками не видно — при быстром скролле строки визуально сливаются.

### 1.4 «Статистика»
- Контент: карточка «Замеры» с выпадающим списком типа, чипы периода (Нед/Мес/3М/Год/Всё/Свой), линейный график; карточка «Тренировки» с теми же чипами периода + две «плитки» показателей (иконка+число).
- Проблемы:
  - **Числа — главный контент экрана статистики — визуально не выделены**: тот же размер шрифта, что и подписи под ними, нет «hero»-эффекта для ключевых метрик.
  - График маленький, зажат отступами, пунктирная линия среднего не подписана (что это?) — шум без объяснения.
  - Двойной ряд чипов периода (Нед/Мес/3М/Год, затем Всё/Свой) съедает много вертикального пространства ради навигации, а не данных.
  - Между двумя карточками нет визуального разделения кроме отступа — при скролле трудно понять, где заканчивается один блок и начинается другой.

### 1.5 «Ещё»
- Контент: плоский список из 5 пунктов меню (иконка+текст), тонкий разделитель перед «Настройки».
- Проблемы:
  - Чистый settings-list без подписей/описаний, без визуальной группировки по смыслу (управление данными vs конфигурация).
  - Ничем не отличается от дефолтного шаблона Material — не считывается как часть «характера» приложения.

### 1.6 Редактор тренировки (S-03) — экран ввода подходов
Дополнительный скриншот от владельца: пустая тренировка-черновик с одним ещё не заполненным упражнением. Это самый частый в реальном использовании экран («в зале, между подходами») — и одновременно самый проблемный из всех.

- Контент: шапка (дата + статус-чип «▾ Черновик», иконка добавления тега — без единого назначенного тега висит в одиночестве без подписи), поле «Комментарий» (0/2000), карточка упражнения (drag-ручка «≡», иконка типа, название, шеврон свернуть/развернуть, меню «⋮»), три строки подходов, «+ Добавить подход», кнопка «+ Добавить упражнение».
- Проблемы (критичные — это экран быстрого ввода одной рукой на бегу):
  - **План и факт визуально неразличимы.** В каждой строке подхода — два пустых одинаковых прямоугольных поля под общей подписью «Вес, кг» (и ещё два под «Повторения») — ничто не подсказывает, какое поле «план», а какое «факт». Пользователю нужно либо помнить порядок, либо гадать на каждый подход. Для контекста «между подходами, потные руки, надо быстро — не глядя вчитываться» это серьёзный барьер.
  - **Подписи полей дублируются на каждой строке.** «Вес, кг» и «Повторения» повторяются как текст-заголовок для каждого из 3 подходов вместо одной общей шапки таблицы — съедает вертикальное пространство ощутимо (на экране умещается всего 3 подхода почти без излишка), увеличивает скролл именно там, где скролл лишний (между подходами хочется видеть весь план тренировки, не листать).
  - **Чекбокс «выполнено» — маленький пустой квадрат-обводка**, визуально почти сливается с соседней иконкой корзины (удаление подхода) того же размера и того же нейтрального серого цвета, стоящей вплотную рядом. Два разных по последствиям действия (отметить готово vs безвозвратно начать удаление) выглядят как близнецы и расположены впритык — прямой риск промаха потным/уставшим пальцем.
  - **Номер подхода («1», «2», «3»)** — мелкий серый текст слева, не выделен, не считывается как якорь при беглом взгляде вниз по списку.
  - Поля ввода — тонкие прямоугольники без единиц измерения внутри, без плейсхолдера-подсказки (просто пусто) — на маленьком экране в движении тяжело понять, какое поле активно/что в него вводить, если не всматриваться.
  - Статус-чип «Черновик» — обычный текстовый dropdown без цвета; ни один из 6 статусов тренировки нигде в приложении не имеет своего цвета — тут это особенно чувствуется, т.к. смена статуса происходит именно на этом экране.
  - «+ Добавить подход» (текстовая ссылка) и «+ Добавить упражнение» (контурная pill-кнопка) — визуально разного веса, хотя по смыслу это действия одного уровня («добавить ещё элемент»); непоследовательный язык кнопок в пределах одного экрана.
  - Иконка тега рядом с датой висит без подписи и без назначенных тегов — неочевидный affordance («что это?») при первом использовании.
  - В сумме: это самый информационно плотный экран приложения (до 4 полей ввода + чекбокс + удаление на каждый подход, при нескольких подходах на упражнение и нескольких упражнениях на тренировку) — и одновременно наименее визуально структурированный. Именно здесь редизайн даст максимальный практический эффект.

### 1.6-доп. Тот же экран в статусе «Выполняется» — активная тренировка с таймерами
Два дополнительных скриншота от владельца закрывают главный пробел из первой версии аудита. Это тот же экран редактора, но в процессе выполнения — с бегущим таймером тренировки и таймером отдыха между подходами. Все проблемы раздела 1.6 здесь актуальны и усиливаются добавлением ещё двух перегруженных строк над и без того плотным списком подходов.

- Контент сверху вниз: системный баннер «Тренировка продолжается N мин / Продолжить», дата + статус-чип «▾ Выполняется», строка бегущего времени «01:26» + кнопка паузы «II», строка таймера отдыха «⏱ Отдых ⊖ 00:40 ⊕ Пропустить», строка «Уведомления выключены», иконка тега, «Комментарий» (уровня тренировки), карточка упражнения с подходами (как в 1.6), «+ Добавить подход» + иконка дублирования подхода, второе поле «Комментарий» (уровня упражнения, 0/1000), сегмент «Прогрессия: — / ↑ / = / ↓», «+ Добавить упражнение».
- Проблемы:
  - **Баннер «Тренировка продолжается» наезжает на статус-бар.** Текст баннера визуально сталкивается с системными иконками (батарея/wifi/сигнал) в самой верхней области экрана — нет отступа под safe area, из-за чего надпись выглядит обрезанной и нечитаемой. Это уже не про «скучно», а про реальный визуальный дефект, который стоит починить в рамках редизайна. Отдельно — баннер показывается даже поверх экрана той же самой тренировки, которую он анонсирует («вы уже здесь, зачем баннер про неё же») — стоит пересмотреть логику показа, не только стиль.
  - **Бегущее время тренировки — главный «герой» экрана по смыслу, но не по форме.** «01:26» набрано тем же мелким шрифтом, что и всё остальное, кнопка паузы — крошечная иконка «II» без выделения. Это единственное число, ради которого человек вообще смотрит на телефон в перерыве между подходами — и оно визуально ничем не отличается от подписи «Комментарий» рядом.
  - **Таймер отдыха — самая тайм-чувствительная строка экрана, но и самая тесная.** «⏱ Отдых ⊖ 00:40 ⊕ Пропустить» — пять мелких элементов (иконка, минус-степпер, время, плюс-степпер, ссылка «Пропустить») втиснуты в одну строку без цветовой/прогресс-индикации (например, полоски или смены цвета по мере истечения времени) — ничем не выделяется на фоне соседних текстовых строк, хотя по частоте использования и цене ошибки — один из важнейших элементов управления в приложении.
  - **Два разных поля с одинаковой подписью «Комментарий»** на одном экране (уровня тренировки — вверху, уровня упражнения — внутри карточки) — по контексту разница считывается, но при беглом взгляде/скролле легко перепутать, какое поле сейчас редактируешь.
  - **Сегмент «Прогрессия: — ↑ = ↓»** — четыре символа без подписей в компактной pill-группе. Без предварительного знания приложения не считывается с первого взгляда, что означает каждый символ (не задан, рост, то же самое, спад) — для новых пользователей это чистый шум на итак плотном экране.
  - Из хорошего, что стоит сохранить: **отмеченный чекбокс подхода визуально контрастен** (заполненный синий квадрат с белой галочкой против пустой серой обводки) — единственный элемент экрана с чётким «state change» эффектом, на который стоит опираться в редизайне остальных состояний.
  - В сумме на экране одновременно присутствуют **минимум 14 разных типов элементов управления** одного и того же (маленького, нейтрального) визуального веса — баннер, статус, 2 таймера, переключатель уведомлений (косвенно), тег, 2 комментария, карточка с drag/меню/чекбоксами/удалением, дублирование, прогрессия. Это самый наглядный пример того, что решает пункт 1 сводки (раздел 4) — здесь редизайн нужнее всего.

### 1.7 Экран-итог тренировки (S-05)
Скриншот от владельца: тренировка с 4 новыми личными рекордами. Это единственный экран в приложении, чья прямая цель — вознаградить/порадовать пользователя за проделанную работу, и именно поэтому расхождение между потенциалом и текущим исполнением здесь особенно заметно.

- Контент: 4 плитки-показателя в сетке 2×2 (иконка+число+подпись: «⏱ 47:00 Длительность», «↗ 1 Упражнения», «✓≡ 4 Подходы», «⊠ 2400.0 кг Тоннаж»), заголовок «Новые рекорды», список из 4 строк (иконка кубка + название упражнения + тип рекорда + значение), поле «Комментарий», блок «Прогрессия».
- Проблемы:
  - **Момент, который должен вызывать эмоцию («4 новых рекорда за одну тренировку!»), выглядит абсолютно нейтрально** — тот же серый `Card`, та же мелкая монохромная иконка (кубок), тот же шрифт, что и на экране настроек. Ни цвета, ни акцента, ни ощущения «награды» — притом что это единственное место в приложении, где такой акцент был бы уместен и мотивирующе оправдан.
  - **Длительность тренировки («47:00») — вероятно самая эмоционально значимая цифра сразу после завершения** — но визуально равна по весу остальным трём плиткам (число упражнений/подходов/тоннаж), хотя по смыслу это не равнозначные метрики.
  - **Название упражнения дублируется 4 раза подряд** («Жим штанги лёжа» перед каждым из 4 рекордов) вместо группировки под одним заголовком с 4 значениями — избыточное повторение текста там, где рекорды принадлежат одному и тому же упражнению.
  - Пометка «расчётный» у 1ПМ подвёрстана под числом мелким текстом справа — легко пропустить, что это не измеренное, а вычисленное значение.
  - Это ровно тот экран, где решение «более смелый/геймифицированный вариант» из Шага 3 даст наибольшую отдачу — стоит явно указать дизайнеру именно этот момент как точку роста.

### 1.8 Сквозные наблюдения по всем экранам
- **Один-единственный цветовой акцент** (`#4C7BD9`, синий) используется одинаково для всего: кнопок, FAB, выделенных чипов, ссылок — нет второстепенных/семантических цветов (успех/предупреждение/статус) для быстрого считывания на бегу.
- **Типографика не выстроена в иерархию**: заголовки экранов, названия карточек, подписи — минимальная разница в размере/весе шрифта, всё это стандартный Material 3 Roboto без кастомизации.
- **Карточки визуально «пресные»**: одинаковый серый `Card` на тёмном фоне почти без контраста, нет теней/акцентных бордеров/разного скругления для разных типов контента.
- **Нижняя навигация** — 5 стандартных `NavigationDestination` с outline-иконками, активное состояние — едва заметная смена цвета/пилюля. В контексте «зал, потные руки, беглый взгляд» это слишком тихо.
- **Нет фирменных иллюстраций/иконографики** — все иконки из стандартного Material Icons, единообразны до неразличимости.
- **Много неиспользуемого пустого пространства** на «Сегодня» и «Истории» (когда записей мало) — не заполнено ни подсказками, ни визуальными элементами.
- Важно: скриншоты показывают только 5 из ~20 реальных экранов приложения. **Не приложены экраны редактора тренировки (S-03) и активной тренировки с таймером/подходами** — а это ровно те экраны, которыми пользуются больше всего именно «в зале, между подходами». Аудит по коду (см. ниже) частично компенсирует этот пробел, но для полноценного редизайна это критический пробел в референсах (см. `NEEDED_FROM_USER.md` на шаге 4).

## 2. Дизайн-система в коде

### 2.1 Тема (`lib/app/theme.dart`)
```dart
const Color seedColor = Color(0xFF4C7BD9);

ThemeData buildLightTheme() => ThemeData(
  colorScheme: ColorScheme.fromSeed(seedColor: seedColor),
  useMaterial3: true,
);

ThemeData buildDarkTheme() => ThemeData(
  colorScheme: ColorScheme.fromSeed(seedColor: seedColor, brightness: Brightness.dark),
  useMaterial3: true,
);
```
- **Один seed-цвет `#4C7BD9`** порождает всю палитру (light и dark) через стандартный алгоритм Material 3 `ColorScheme.fromSeed` — никаких вручную заданных дополнительных цветов, никакого кастомного `ColorScheme(...)`.
- **Нет ни одной кастомизации компонентов темы**: не заданы `cardTheme`, `appBarTheme`, `textTheme`, `filledButtonTheme`, `navigationBarTheme`, `chipTheme` и т.д. — буквально всё, что видно на скриншотах, это дефолтный вид Material 3 виджетов Flutter.
- **Правило в коде** (комментарий в файле): «Colors must always be read from `Theme.of(context).colorScheme` in widgets, never hardcoded» — соблюдается по всему проекту (подтверждено отдельным аудитом на Этапе 9, единственное обоснованное исключение — белая галочка на цветном свотче тега).

### 2.2 Шрифты
- Кастомных шрифтов в `pubspec.yaml` нет (секция `fonts:` закомментирована, ничего не подключено) → используется системный шрифт платформы (Roboto на Android, San Francisco на iOS через Material-рендеринг).
- Кастомного `TextTheme` нет — везде используется дефолтная типографическая шкала Material 3 (`Theme.of(context).textTheme.titleMedium/bodySmall` и т.п. без переопределений размеров/весов/interletter spacing).

### 2.3 Spacing / radius
- **Единой шкалы отступов не существует.** Значения `EdgeInsets`/`SizedBox` заданы вручную по месту, в коде встречаются как минимум: `4, 8, 12, 16, 24` (px/dp) — без общей константы или токена.
- `BorderRadius` нигде явно не переопределяется — везде дефолтные скругления Material 3 виджетов (`Card` ≈12dp, `FilledButton`/`OutlinedButton` — полная пилюля по стандарту M3).
- Как следствие: **нет закреплённой в коде spacing-шкалы** (например, 4/8/12/16/24/32) — это придётся ввести с нуля вместе с редизайном, а не «извлечь».

### 2.4 Переиспользуемые виджеты
- **Общей библиотеки компонентов (кнопка/карточка/инпут) нет.** Каждый экран строит свой `Card(child: ListTile(...))`, свои `OutlinedButton`/`FilledButton` напрямую — паттерн повторяется ~20+ раз по разным файлам без общей обёртки.
- Единственный по-настоящему переиспользуемый визуальный элемент — `lib/core/widgets/error_retry_state.dart` (`ErrorRetryState`): иконка + текст + кнопка «Повторить», используется на 27 экранах для одного и того же паттерна ошибки загрузки.
- Единственная зафиксированная в коде «мини-палитра» вне темы — `lib/core/constants.dart`:
  ```dart
  const List<String> workoutTagColorPalette = [
    '#4C7BD9', '#2E9E6B', '#D9774C', '#B34CD9',
    '#D9B84C', '#4CC3D9', '#D94C6B', '#7B8794',
  ];
  ```
  8 фиксированных hex-цветов для тегов тренировки — единственное место, где в приложении используется палитра шире одного seed-цвета.
- Числовые поля ввода (вес/повторения/дистанция и т.п.) реализованы через общий `SetNumberField` с настраиваемой клавиатурой (дробная/целая) — единственный по-настоящему переиспользуемый инпут-компонент.

### 2.5 Иконки
- Иконографика — исключительно стандартный `Icons.*_outlined` набор Material Icons (например `Icons.today_outlined`, `Icons.history_outlined`, `Icons.fitness_center_outlined`, `Icons.bar_chart_outlined`, `Icons.more_horiz_outlined` для нижней навигации). Кастомных/брендированных иконок нет.

## 3. Навигация и архитектура

- **Навигация**: `go_router` (v17), `StatefulShellRoute.indexedStack` с 5 табами: Сегодня / История / Упражнения / Статистика / Ещё (`lib/app/router.dart`). Каждый таб хранит собственный стек навигации. Формы создания/редактирования всегда открываются как full-screen modal (`fullscreenDialog: true`), просмотровые/детальные экраны — обычный push.
- **Нижняя навигация**: стандартный `NavigationBar` (Material 3), 5 пунктов, повторный тап по активной вкладке сбрасывает её стек к корню.
- **State management**: Riverpod (`flutter_riverpod` 3.x) — `StreamProvider`/`FutureProvider`, часто `.family`/`.autoDispose`, `ConsumerWidget`/`ConsumerStatefulWidget` повсеместно.
- **Платформы**: только **Android и iOS** — веб/Linux/macOS/Windows-таргеты были явно удалены на самом старте проекта. iOS-сборка при этом ни разу не собиралась и не проверялась вживую за весь цикл разработки (нет macOS в рабочей среде) — интерфейс полностью на Material-виджетах, Cupertino не используется нигде (сознательное решение, не тема для пересмотра в рамках этого редизайна, но стоит держать в уме: на iOS это будет выглядеть «не нативно» уже сегодня, редизайн эту особенность не меняет).
- **Хранилище**: Drift/SQLite, полностью локально, бэкенда/аккаунтов/авторизации нет — соответственно, нет экранов логина/онбординга (онбординг first-run осознанно не делался, см. ниже).
- **Локализация**: RU/EN через ARB-файлы, переключается на лету; русский текст в среднем длиннее английского ~в 1.3 раза — layout уже проверялся на переполнение (`TextOverflow.ellipsis` + tooltip на длинных именах, `isExpanded` на дропдаунах).
- **Доступность**: в проекте уже проведён отдельный аудит на тач-таргеты (минимум 48×48dp), `Semantics`-подписи на иконках-кнопках, поддержка масштаба текста до 1.6× — это была осознанная работа (Этап 9), редизайн не должен её регрессировать.
- **Иконка/сплэш**: не сделаны, стоят дефолтные ассеты `flutter create` — дизайн иконки/сплэша прямо назван открытым, отложенным пунктом («нет готового арта»).

## 4. Сводка ключевых проблем (для DESIGN.md)

1. **Редактор тренировки (S-03), особенно в статусе «Выполняется», — приоритет №1.** Поля «план» и «факт» неразличимы, чекбокс «выполнено» и кнопка удаления подхода визуально почти идентичны и расположены впритык (риск промаха), подписи полей дублируются на каждой строке вместо общей шапки таблицы. В активном статусе добавляются ещё две тайм-чувствительные строки (бегущий таймер тренировки, таймер отдыха между подходами), которые визуально ничем не выделены среди остального текста, хотя это самые важные элементы экрана именно в моменте «между подходами». Плюс реальный визуальный дефект — системный баннер наезжает на статус-бар. Это самый частоиспользуемый в реальном контексте (зал, между подходами, одной рукой, потные руки) экран — и одновременно самый проблемный с точки зрения юзабилити, не только эстетики.
2. Дизайн-система — по факту **не существует за пределами одного seed-цвета**: нет типографической шкалы, нет spacing/radius токенов, нет темизированных компонентов. Редизайн придётся начинать с нуля, а не «освежать» существующее.
3. **Нулевая визуальная иерархия** между элементами разной важности (заголовок карточки vs метаданные, ключевая метрика статистики vs подпись, статус тренировки vs остальной текст).
4. **Один цветовой акцент на всё** — нет семантического цвета для статусов (черновик/план/в процессе/завершена/пропущена/отменена), нет способа мгновенно считать состояние глазами в движении. Особенно заметно на статус-чипе редактора тренировки.
5. **Каталог упражнений** (199 строк) визуально неразличим — самый «скучный» экран приложения, при этом один из самых часто открываемых.
6. **Статистика** не выделяет числа как главный контент — цифры и подписи к ним визуально равны.
7. **Нижняя навигация и кнопки** технически уже соответствуют минимуму тач-таргета (48dp), но визуально «тихие» — не спроектированы для быстрого распознавания на бегу/с потными руками/боковым зрением.
8. Ключевые скриншоты (статичный редактор, активная тренировка с таймерами, экран-итог) теперь приложены — основной пробел из первой версии аудита закрыт. Остаются не показанными: экран одного упражнения из каталога (S-07) и форма создания упражнения (S-08) — не критично для брифа, но стоит упомянуть дизайнеру как экраны «за кадром», которые тоже используют ту же систему компонентов и получат тот же редизайн автоматически.
9. **Экран-итог тренировки (S-05) — упущенная точка эмоционального вознаграждения.** «4 новых рекорда» подаются с тем же нейтральным весом, что и список настроек — единственное место в приложении, где уместен более смелый/геймифицированный визуальный язык, и это стоит явно предложить дизайнеру как отдельное направление (см. вариации промтов в Шаге 3).
